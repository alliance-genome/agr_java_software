# SCRUM-5964 — Gene File Generator

## Summary

The new `GeneFileGenerator` reads from the `gene_summary` category in `site_index` and writes per-MOD plus COMBINED TSV + JSON output (`GENE-{TSV,JSON}_{MOD|COMBINED}.{tsv,json}.gz`). MOD whitelist: `FB`, `MGI`, `RGD`, `SGD`, `WB`, `XBXL`, `XBXT`, `ZFIN` (no HUMAN — same convention as the Expression generator).

One row per gene_summary doc. The doc is the curation API's `GeneSummaryDocument` (a thin wrapper over the full `Gene` entity) — every field we expose comes from the embedded `gene` subtree.

## ES query equivalent

```json
{
  "from": 0, "size": 1,
  "query": {
    "bool": {
      "filter": [
        { "term": { "category.keyword": "gene_summary" } },
        { "term": { "gene.primaryExternalId.keyword": "HGNC:11998" } }
      ]
    }
  }
}
```

## TSV columns (17 total)

| Column | ES path / source |
|---|---|
| Taxon | `gene.taxon.curie` |
| SpeciesName | `gene.taxon.name` |
| GeneId | `gene.primaryExternalId` |
| GeneSymbol | `gene.geneSymbol.displayText` |
| GeneSynonyms | synthetic `_geneSynonyms` — pipe-joined `gene.geneSynonyms[].displayText` |
| GeneSystematicName | `gene.geneSystematicName.displayText` |
| GeneSecondaryIds | synthetic `_geneSecondaryIds` — pipe-joined `gene.geneSecondaryIds[].secondaryId` |
| GeneCrossReferences | synthetic `_geneCrossReferences` — see below |
| GeneBioTypeId | `gene.geneType.curie` (Sequence Ontology curie) |
| GeneBioTypeName | `gene.geneType.name` |
| GeneAutomatedDescription | synthetic `_automatedDescription` — `gene.relatedNotes[]` entry where `noteType.name == "automated_gene_description"` |
| GeneMODDescription | synthetic `_modDescription` — `gene.relatedNotes[]` entry where `noteType.name == "MOD_provided_gene_description"` |
| Assembly | synthetic `_assembly` — `gene.geneGenomicLocationAssociations[0].geneGenomicLocationAssociationObject.taxon.species.assembly_curie` |
| Chromosome | `gene.geneGenomicLocationAssociations.0.geneGenomicLocationAssociationObject.name` |
| StartPosition | `gene.geneGenomicLocationAssociations.0.start` |
| EndPosition | `gene.geneGenomicLocationAssociations.0.end` |
| Strand | `gene.geneGenomicLocationAssociations.0.strand` |

### GeneCrossReferences formatting

Bar-separated `referencedCurie` values from `gene.crossReferences[]`. The single GCRP cross reference (`gene.gcrpCrossReference.referencedCurie`) is matched against the list and that one entry is suffixed with ` (GCRP)`. Example fragment:

```
NCBI_Gene:7157|HGNC:11998|UniProtKB:P04637 (GCRP)|UniProtKB:Q53GA5|...
```

### Description fields

`relatedNotes` is an array of `{noteType:{name}, freeText}` objects. We pull whichever entry's `noteType.name` matches the requested type:

- `automated_gene_description` → GeneAutomatedDescription column (generated by the automated-gene-description pipeline, persisted as a Note on the gene)
- `MOD_provided_gene_description` → GeneMODDescription column (curator-provided / loaded from the MOD's data feed)

Both render blank when the corresponding note isn't present on the gene.

### Genome location

A gene may carry multiple `geneGenomicLocationAssociations` (different assemblies, MT vs nuclear, etc.). We emit the first one — same convention the website's gene page uses for the headline location. The Assembly column reads `…taxon.species.assembly_curie` from the same association so the assembly stays consistent with the chromosome/position values.

## File layout produced

`GENE-{TSV,JSON}_{MOD}.{tsv,json}.gz` per allowed MOD, plus `GENE-{TSV,JSON}_COMBINED.{tsv,json}.gz`. JSON outputs use the framework's `{metadata, data: [<raw _source>...]}` shape (same policy as Disease and Expression).

## JSON metadata header

```json
"metadata": {
  "filetype": "Gene",
  "databaseVersion": "<ALLIANCE_RELEASE>",
  "sourceURL": "https://www.alliancegenome.org/downloads",
  "genTime": "<UTC yyyy-MM-dd HH:mm>",
  "dataFormat": "json",
  "stringencyFilter": null,
  "readme": "<readmes/gene.txt one-line content>",
  "species": [{"taxonId": "...", "speciesName": "..."}, ...]
}
```

## Wiring

Pure framework reuse — no changes to `Main`, `FileGenerator`, `HeaderBuilder`, or any writer:

- New `GeneFileGenerator extends FileGenerator` (delegates to `scrollAndWrite()`, computes synthetic fields in `customizeRow`)
- New `Gene` entry in the `FileGeneratorConfig` enum (auto-discovered by `Main`)
- New `readmes/gene.txt` resource

## Reused framework features

- Sliced parallel scroll (8 slices, 1000-doc buffer per slice)
- `_source` filtering — the field map values plus the explicit `additionalSourceIncludes` list (synonyms, secondaryIds, crossReferences, gcrpCrossReference, relatedNotes, geneGenomicLocationAssociations) — synthetic `_*` paths are skipped automatically
- MOD whitelist gating per-MOD output files
- TSV banner header + COMBINED + per-MOD splits
- JSON metadata + raw _source data array
